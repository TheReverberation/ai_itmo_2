# WORKLOG

План на старте: сначала зафиксировать целевую архитектуру (два пути, HITL, деградация), затем минимальный PoC с тестами, затем остальные обязательные доки; продуктовую часть делать только если останется запас времени. Этот порядок виден в истории коммитов: архитектура → PoC → ml.md и monitoring.md → risks-and-ops.md → README/AI_USAGE/SELF_REVIEW → опциональный product.md в самом конце.

Что пошло не по плану: Mermaid-диаграммы не рендерились на GitHub из-за переносов строк в узлах — потребовался отдельный коммит с фиксом; на формулировку каскада правила→ML→LLM в ml.md ушло больше времени, чем закладывал.

Что сознательно вырезано из скоупа и почему:
- очередь и асинхронные воркеры в PoC — оставлены только в дизайне (architecture.md): к доказательству happy/fallback path они не добавляют, а времени стоят непропорционально много;
- настоящие embeddings и vector store — заменены TF-IDF на stdlib, чтобы PoC запускался без зависимостей;
- обучение реальной модели классификации — заменено правилами с суррогатным confidence (обучение на большом датасете прямо исключено условием задания);
- UI оператора — не проектировался (также исключено условием).

Продуктовую часть (product.md, для «ИИ» опциональную) успел сделать эскизно в последние минуты тайм-бокса — как плюс, а не как полный артефакт AI Product.

На финальной вычитке перед сдачей нашёл и закрыл слабость PoC: ветка suggest-режима (`suggest_to_operator`) была недостижима на демо-данных — добавил тикет t-007 и седьмой smoke-тест, чтобы все три исхода политики (auto_draft / suggest / escalate) были видны в demo.
