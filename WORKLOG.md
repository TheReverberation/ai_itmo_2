# WORKLOG

План на старте: 20 минут на каркас и скелеты документов, ~70 минут на архитектуру и ML-дизайн, ~70 минут на PoC с тестами, остаток — product, monitoring, риски и вспомогательные файлы, финальная проверка в конце.

По факту порядок слегка изменился: архитектуру и ml.md написал до PoC — это окупилось, потому что PoC собрался как прямая проекция уже принятых решений (правила + TF-IDF + mock-LLM) и не потребовал переделок.

Сознательно вырезано из скоупа: HTTP API и контейнеризация (PoC — CLI-скрипты, очереди заменены последовательными вызовами — это честно помечено в коде и docs); реальные embeddings и внешний LLM API (TF-IDF и шаблонный генератор демонстрируют те же контрактные точки); обучение любой модели (задание явно это запрещает); UI оператора (operator_inbox — JSONL-файл).

Единственная «роскошь», которую оставил: отдельный тест на fallback при недоступности LLM — деградация без LLM была центральным требованием кейса, и её надо было показать делом, а не только текстом.
