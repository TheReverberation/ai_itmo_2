# Риски и эксплуатация

## Highload и надёжность

- **Sync vs async:** на синхронном пути только то, что обязано быть быстрым (нормализация, PII-mask, классификация, маршрутизация — ≤500 мс); всё, что зависит от LLM (retrieval, генерация), — за очередью. Отказ асинхронной части не ломает маршрутизацию.
- **Пики и очереди:** всплеск 10–20k тикетов/10 мин гасится очередью с backpressure; инцидентная дедупликация схлопывает похожие тикеты в кластер — один черновик на инцидент вместо тысяч вызовов LLM (в PoC: `loadguard.py`, `python -m app.demo_spike`).
- **Недоступность LLM:** circuit breaker + таймауты; деградация по ступеням: LLM → retrieval-only (шаблон из статьи KB, в PoC — при исчерпании ₽-бюджета) → шаблонное подтверждение + оператор. Безопасное состояние = «как было до автоматизации», а не отказ в обслуживании.
- **Разделение путей (bulkhead):** быстрый путь классификации и медленный путь генерации не делят ресурсы и деплоятся независимо — деградация генерации не может съесть латентность маршрутизации.

## Privacy, safety и risk

- **PII:** маскирование (Presidio: pattern-рекогнайзеры + локальный NER) выполняется внутри контура **до** любого внешнего вызова; во внешний LLM API уходит только маскированный текст, сырой текст и ключи PII живут только во внутренних хранилищах с ограниченным доступом.
- **Что нельзя закрывать автоматически:** споры по оплате/возвратам, ПДн-запросы, подозрение на взлом/мошенничество, юридические претензии, упоминания вреда — всегда human-in-the-loop; правило риска переопределяет любую уверенность модели (в PoC: `risk=high` → эскалация до генерации), список меняется только через review.
- **Prompt injection:** текст тикета передаётся в LLM строго как данные (отделён от инструкций — в PoC демо-тикет t-008 и тест); выход проходит output gate (нет PII-плейсхолдеров, groundedness по KB — в PoC `passes_output_gate`); **LLM не имеет инструментов и доступов — только генерация текста**, поэтому даже успешная инъекция ограничена содержимым одного черновика, который до режима auto видит оператор.
- **Аудит:** каждое автоматическое решение — в append-only decision log (вход после маскирования, версия модели и промпта, confidence, retrieval-источник, результат gate, кто подтвердил); kill switch на автозакрытие; выборочный еженедельный ручной аудит автоответов. Лог отвечает на вопрос «почему система так решила» и служит источником разметки.
