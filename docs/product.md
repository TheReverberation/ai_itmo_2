# Продуктовый дизайн (эскиз)

> Для программы «ИИ» этот артефакт необязателен — здесь эскиз ключевых продуктовых решений.

## Проблема и ценность

- **Оператор:** меньше однотипной рутины — типовые тикеты приходят с готовым черновиком и контекстом, время уходит на сложные случаи, а не на копипасту из базы знаний.
- **Пользователь:** ответ на типовой вопрос за минуты вместо ожидания в общей очереди; рискованные вопросы по-прежнему решает человек.
- **Бизнес:** снижение стоимости обработки потока (150 ₽/тикет × 200k/день) и удержание SLA в пиках без пропорционального роста штата поддержки.

## Бэклог гипотез (приоритизация: эффект × охват / риск × стоимость проверки)

| # | Гипотеза | Эффект | Охват | Риск | Стоимость проверки |
|---|---|---|---|---|---|
| 1 | Черновик ответа оператору (suggest) | высокий | ~40% потока | низкий (человек в контуре) | низкая |
| 2 | Маршрутизация по теме/риску | средний | 100% потока | низкий | низкая (shadow) |
| 3 | Автозакрытие безопасных категорий | высокий | 10–20% | средний | средняя (после 1) |
| 4 | Дедупликация при инцидентах | средний | пики | низкий | низкая |
| 5 | Суммаризация треда для оператора | средний | сложные тикеты | низкий | средняя |
| 6 | Автоответ по FAQ до создания тикета | средний | часть потока | средний | средняя |

**Почему сверху 1 и 2:** оба проверяются дёшево и без риска для пользователя (человек в контуре / shadow), покрывают большую часть потока и являются фундаментом для всего остального — автозакрытие (3) без проверенных черновиков и маршрутизации невозможно.

- **Гипотеза 1 (suggest-черновики):** операторам N пилотных категорий показываем черновик + confidence. Ожидание: −30% времени обработки типового тикета (8 → ~5,5 мин), метрика — среднее время обработки и доля черновиков «принят без правок». Проверка: пилот на 2–3 категориях, 2 недели, A/B по операторам. Откат, если доля «принят без правок» < 30% или время обработки не падает.
- **Гипотеза 2 (маршрутизация):** классификатор в shadow против ручной маршрутизации 2 недели. Ожидание: точность маршрута ≥ текущей ручной, минус один ручной шаг. Откат, если точность ниже ручной или recall по рискованным категориям < 0.95.

## Метрики

- **North Star:** доля тикетов, закрытых без оператора, при неухудшении CSAT.
- **Guardrails:** reopen rate авто-когорты ≤ 9% (базовый уровень); CSAT авто-когорты ≥ операторской − 0,1; SLA breach rate первого ответа не выше текущего.

## Расчёт эффекта (год, при выходе на автозакрытие ~20% потока)

| Строка | Значение | Assumption |
|---|---|---|
| Поток тикетов в год | 73 млн | 200k/день × 365 |
| Автоматизировано (авто-закрытие) | 14,6 млн (20%) | половина от 40% типовых — консервативно |
| Экономия операторского времени | **≈ 2,2 млрд ₽/год** | 14,6 млн × 150 ₽ |
| Стоимость LLM-инференса | ≈ 45–90 млн ₽/год | черновики на ~40% потока, ~3k токенов/тикет, 0,5–1 ₽/1k токенов |
| Команда + инфраструктура | ≈ 60–80 млн ₽/год | 5–6 человек + вычислительные ресурсы |
| **Чистый эффект** | **≈ 2,0 млрд ₽/год** | чувствительность ниже |

Чувствительность к reopen rate: каждый +1 п.п. reopen в авто-когорте — это ~146k тикетов обратно к операторам ≈ 22 млн ₽/год прямых затрат плюс удар по CSAT; при reopen > ~12% доверие к автоматизации теряется быстрее, чем экономятся деньги (критерий остановки — в [SELF_REVIEW](../SELF_REVIEW.md)).

## План раскатки и пилот

Этапы: **shadow** (решения в лог, пользователю ничего) → **suggest** (черновик оператору) → **auto** (только безопасные категории, поштучное включение).

| Майлстоун | Длительность | Результат |
|---|---|---|
| M1: классификатор + shadow | 3–4 недели | точность маршрутизации на живом потоке |
| M2: suggest в 2–3 категориях | 3 недели | доля «принят без правок», время обработки |
| M3: автозакрытие 1–2 безопасных категорий | 3 недели | reopen/CSAT авто-когорты vs guardrails |
| M4: расширение категорий + инцидент-режим | 4 недели | масштабирование по данным M2–M3 |

Команда: ML-инженер ×2, backend ×2, продакт, разметка/аналитика поддержки (part-time тимлид поддержки как доменный эксперт).
